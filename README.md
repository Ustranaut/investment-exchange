# Биржа инвестиционных пакетов — учебный симулятор

Учебный веб-проект на **Python + Django + PostgreSQL**. Проект объединяет публичную витрину пакетов, личный вход пользователей, административную панель и демонстрационные котировки.

> **Важно:** это исключительно учебный макет. Проект не является финансовой услугой, инвестиционной платформой или предложением вложить деньги. Реальные платежи и инвестиционные операции не выполняются. Все цены, котировки и показатели доходности демонстрационные.

## Возможности проекта

### Публичная витрина
- Каталог активных пакетов.
- Поиск по названию и описанию.
- Страница подробной информации о пакете.
- Отображение цены в российских рублях (₽).
- Отображение срока, условной доходности и доступного лимита.

### Пользователи и роли
- Клиент (`client`).
- Менеджер (`manager`).
- Супер-администратор (`superadmin`).
- Авторизация на стандартных механизмах Django.
- Проверка доступа к панели управления на сервере.

### Административная часть
- Управление пакетами через Django Admin.
- Управление пользователями и ролями.
- Просмотр и изменение заказов.
- Управление акциями и промокодами.
- Управление демонстрационными котировками.
- Модель и административный просмотр журнала действий (автоматическое логирование бизнес-событий — следующий этап).

### Модели и бизнес-логика
- Заказы сохраняют снимок параметров пакета на момент оформления.
- Резервирование лимита пакета выполняется в транзакции PostgreSQL.
- При отмене заказа резерв освобождается.
- Для цен и сумм используется `DecimalField` / PostgreSQL `NUMERIC`, не `float`.
- Подготовлены модели акций, промокодов, истории котировок и аудита.

## Быстрый запуск

### Требования
- Git.
- Docker Desktop (Windows/macOS) или Docker Engine + Docker Compose (Linux).

### 1. Склонировать репозиторий

```bash
git clone https://github.com/ВАШ_ЛОГИН/investment-exchange.git
cd investment-exchange
```

### 2. Создать локальный файл окружения

Linux / macOS:

```bash
cp .env.example .env
```

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Файл `.env` содержит локальные настройки и не должен попадать в GitHub.

### 3. Запустить проект

```bash
docker compose up --build
```

При первом запуске контейнер:
- дождётся готовности PostgreSQL;
- создаст начальные миграции для учебных приложений;
- применит миграции;
- добавит демонстрационные пакеты;
- запустит Django.

Откройте сайт: http://localhost:8000

Django Admin: http://localhost:8000/admin/

> После первого запуска проверьте созданные файлы `apps/*/migrations/` и добавьте их в Git. В дальнейшем миграции нужно создавать и коммитить при каждом изменении моделей. Автоматическая генерация миграций в entrypoint предназначена только для удобного первого запуска учебного проекта, а не для production.

### 4. Создать администратора

В новом окне терминала:

```bash
docker compose exec web python manage.py createsuperuser
```

Следуйте подсказкам Django. Созданный суперпользователь сможет войти в Django Admin.

Чтобы открыть дашборд, назначьте пользователю роль `superadmin` в разделе Users административной панели.

### 5. Остановить проект

```bash
docker compose down
```

Чтобы также удалить локальные данные PostgreSQL:

```bash
docker compose down -v
```

**Внимание:** команда с `-v` удаляет базу данных проекта.

```text
├── apps/
│   ├── users/        # Пользователи и роли
│   ├── packages/     # Каталог пакетов

├── static/           # CSS, JavaScript, изображения
├── Dockerfile
├── compose.yaml
├── requirements.txt
├── .env.example
├── README.md
└── manage.py
```

## Полезные команды

```bash
# Посмотреть запущенные контейнеры
docker compose ps

# Открыть Django shell
docker compose exec web python manage.py shell

# Проверить конфигурацию Django
docker compose exec web python manage.py check

# Создать миграции после изменения моделей
docker compose exec web python manage.py makemigrations

# Применить миграции
docker compose exec web python manage.py migrate

# Повторно добавить демонстрационные пакеты
docker compose exec web python manage.py seed_demo
```

## Публикация сайта в интернете через GitHub + Render

GitHub хранит исходный код, а Render запускает Django-приложение.

1. Загрузите содержимое репозитория на GitHub.
2. Откройте https://render.com/ и войдите через GitHub.
3. В Render выберите **New → Blueprint**.
4. Подключите репозиторий `investment-exchange`.
5. Render прочитает `render.yaml`. Проверьте выбранные планы ресурсов и возможную стоимость, затем нажмите **Apply**.
6. Дождитесь статуса **Live** и откройте выданный адрес `*.onrender.com`.

После первого успешного развёртывания создайте администратора через Shell сервиса Render:

```bash
python manage.py createsuperuser
```

Публичный бесплатный сервис может засыпать после периода бездействия; доступность бесплатного PostgreSQL и срок его хранения зависят от текущих тарифов Render. Проверьте условия в панели перед подтверждением.
